# 嘉宾英文洞察与分享流程

2026-09-15用户确认分发路径：**立正在LinkedIn和X发核心insights→艾特已核实嘉宾→链接英文全文→立正亲自nudge嘉宾repost原帖**。嘉宾自行撰写配文不再是主路径。

这条内容线服务两个读者：想快速读懂一场中文访谈的英文读者，以及希望把自己的判断分享给同行的嘉宾。沿用Superlinear Academy / Conversations；访谈主体和嘉宾获得清楚的署名。每篇先交付值得独立阅读的内容，再提供方便分享的材料。

## 一期访谈的完成标准

1. **来源**：先合并同一场录制的完整版、精剪和切片。记录实际使用版本、时间范围、说话人、公开原片链接和访谈日期。姓名、嘉宾角色、关键数字有来源；历史任职用访谈时态。库存中的匿名嘉宾、组合嘉宾和疑似重复身份保留待核状态。
2. **英文洞察稿**：标题表达一个有张力的核心判断；副标题带嘉宾姓名和主题；开篇4–6条TL;DR；其后40–80词嘉宾介绍；正文围绕4–8个重要判断，保留推理、具体案例、约束和反例。一般900–1,600词，内容决定长度。只有足够实质材料的短访谈才做短稿。
3. **忠实审校**：逐项回到逐字稿检查：谁说的、原话条件、数字口径、时间线、例子能否支持结论。引号只留给可准确回译的原话；英文编辑归纳用转述。平台标题、旧伴读和ASR不能互相循环证明。没有正文证据时不根据履历或标题编摘要。
4. **封面与元数据**：真实嘉宾画面或经核对的官方照片；英文可读标题；使用Superlinear Academy文字刊头；若使用图形标识，须用官方六层资产，不生成替代logo。沿用#238343。1536×1024主图，关键信息同时兼容3:2封面和1.91:1社交预览。检查手机缩略图、姓名拼写、SEO标题/描述、免费全文与来源链接。
5. **一次审阅包**：全文、封面、元数据、原文依据、发布位置与受众、嘉宾页精确diff在同一个本地审阅页。冻结内容hash。已审核内容发生实质改动后重新审阅，避免把旧批次批准沿用到新文章。
6. **上线与回填**：批准后先在现有Substack发布，仅网页回填历史内容；记录真实postId、URL、公开时间、通知开关与核验。随后把实际链接回填个人嘉宾页。嘉宾页只放独立介绍、3条重点和英文全文入口，不复制全文；保留原视频、频道入口和已有稳定URL。
7. **立正社交帖与嘉宾转发**：LinkedIn写约180–280词，先给核心判断，再用2–3个具体例子展开；X用一条能独立成立的主帖，必要时附2条短回复，主帖含英文全文链接。用立正身份说清楚从访谈学到了什么。只艾特已核实的嘉宾账号，LinkedIn必须选择原生mention；无可靠X账号就留空并记录。正文、封面、受众和mention目标先纳入整批审阅。批准后发布并核实真实原帖URL，再提供一句中文nudge和两平台原帖链接，**由立正亲自转给嘉宾**。不代表嘉宾认可内容，不自动发DM。
8. **交付核验**：公开全文、TL;DR、姓名/简介、封面裁切、源链接、canonical、可索引状态、免费阅读、嘉宾页回链、分享链接逐项回读。Substack的存在或sitemap条目不等于Google已收录。

每次常规运行完成一个有边界的批次：先处理已批准的发布或实际故障，再推进最多3篇源材料已经足够的正文。全量补库是持续队列，不以数量替代文章质量。写完但未审校、已建稿但未公开、已公开但未回链都不是最终完成。

## 自动化与人的分工

沿用现有`superlinear`周一/四自动化读取的`current-focus.md`，不另起重复定时任务。自动执行的默认终点是可审阅草稿；发布边界要求本批精确批准。助手承担检索、去重、英文写作、事实核对、封面、原生建稿、网页实现、核验、链接回填及统计。立正只需整批审阅，然后选择是否把材料转给嘉宾；不需要组织活动或重新录制。

当前常规每周额度按既有章程15%规划、20%软上限，不将账户总用量或token数冒充本项目配额。当前明确补库请求与例行复盘分开记录；后续每次运行按剩余预算选择批次大小，不偷偷兑换额度。

## 怎么提高

保留现有Simon Willison对标中的做法：连接一手材料，增加自己的清楚归纳，给读者可检验的具体证据。用于访谈时，最小编辑单元是“判断→原案例→机制→适用边界”，而非按主持人的问题逐条翻译。

先人工检验首两篇：英文读者读完TL;DR能否复述核心判断；正文至少有三个不可互换的具体例子；嘉宾是否会觉得观点被准确表达。每批记下一项实际问题和下一次改变，不同时更改标题、结构、封面与分发方法来追逐无法归因的数字。

发布后在能取得数据时记录7天/28天实际年龄、来源访问、继续阅读及订阅。立正原帖使用平台可区分的UTM链接；记录原帖URL、嘉宾mention是否实际成立、能观察到的repost以及原生链接点击。嘉宾repost仍指向原帖，不另建重复社交帖或强迫嘉宾写文。未知分享与未知归因记null。避免把点赞、单次嘉宾曝光或短期订阅波动当成已验证增长方法。嘉宾反馈优先纠正准确性，再改可读性。

## 命令与状态

`python3 tools/build_release.py`生成文章校样、总审阅页、分享包及待执行清单，默认不联网也不发布。

`python3 tools/check_release.py`核对文本、来源、链接、封面与待审项；未满足条件的条目继续排队。

`python3 tools/check_release.py --execution-ready`额外要求本批批准hash和准确目标一致。脚本只检查执行前提，不直接发布；原生执行后由真实回读结果写入`publication-results.json`，不得预写成功。

状态顺序：`source_pending` → `source_ready` → `draft` → `qc_passed` → `review_ready` → `approved` → `published` → `published_verified` → `guest_page_verified` → `social_published_verified` → `nudge_ready`。`existing_thematic_article`是覆盖类型，不是访谈摘要完成状态。
