# 媒体库维护规则

本项目以后不要再用目录名判断业务状态。`archive/有人工字幕`、`archive/无人工字幕` 是历史存储位置，不是 source of truth。

## Source of truth

每个视频的 canonical 状态由这个命令生成：

```bash
python3 tools/check/build_library_manifest.py
```

输出在：

- `logs/library_manifest/library_manifest.json`
- `logs/library_manifest/library_audit.md`

这两个文件是运行时审计产物，放在 `logs/` 下，不提交。

## Canonical fields

每条视频记录至少看这些字段：

- `video_id`: YouTube video id，唯一键。
- `folder`: 本地物理位置。
- `folder_category`: 历史目录名，只说明文件在哪里。
- `youtube_privacy`: 当前 YouTube 快照中的 `public` / `unlisted` / `private` / `not_in_current_uploads`。
- `content_class`: 从 `info.json.availability`、`live_status`、`was_live` 判断出的 `normal_video` / `member_only` / `live_replay`。
- `transcript_status`:
  - `human`: `info.json.subtitles` 里有中文或英文人工字幕。
  - `local_corrected`: 有本地精校后的 `.corrected.srt`。
  - `local_qwen_uncorrected`: 有本地 Qwen ASR，但还没精校。
  - `downloaded_auto`: 有 YouTube 自动字幕。
  - `timed_unknown`: 有 timed subtitle 文件，但来源无法确认。
  - `missing`: 没有可用 timed subtitle。
- `podcast_policy`:
  - `ready_public_normal`: public + normal video，可进 Transistor；字幕质量另看 `transcript_status`。
  - `not_podcast_member_only`: member-only，不进公开 Transistor。
  - `not_podcast_live_replay`: 直播回放，不进公开 Transistor。
  - `not_public`: unlisted/private/当前 YouTube 不可见，不自动进公开播客。
- `transistor_status`: `published` / `draft` / `absent`。
- `action_needed`: 下一步动作。

## Podcast sync rule

自动同步到公开 Transistor feed 的条件：

1. `youtube_privacy == "public"`
2. `content_class == "normal_video"`
3. `transistor_status != "published"`

`transcript_status` 不是 Transistor 发布硬门槛。同步计划会为所有可定位的本地
SRT/VTT 选择确定的最高优先级来源，转成纯文本，并通过 Transistor 官方 API 的
`episode[transcript_text]` 写入。公开 API 不提供原始 SRT 文件上传字段，因此这条
自动化保留字幕文字、但不保留 cue 时间戳；原始 timed 文件仍以本地 archive 为权威源。

发布 description 的优先级是：`podcast_show_notes/<video_id>.txt` > archive 内非空的
`*.podcast-description.txt` > 非空的本地 `.description` > 新鲜 YouTube 快照中的
description。前两种是播客专用 show notes；后两种只是 YouTube 文案回退。最终正文、来源
和 SHA-256 一起锁进不可变计划。全部为空时记为质量 warning，但不阻止符合 public +
normal video 规则的 episode 发布。

播客专用 show notes 必须通过 `tools/podcast/show_notes.py` 的确定性校验：不超过
10,000 字符、Transistor 动态标签在允许列表内、时间戳严格递增。旧社区域名和非 canonical
入口记为 warning。已有 published episode 只有出现这个播客专用 sidecar 时，才生成独立
的 `description_actions`；普通 `.description` 或 YouTube 快照永远不会触发历史批量改写。

来源优先级：`.corrected.srt` / `.final.srt` > 已确认人工语言字幕 > 普通 SRT >
VTT > 未校正 Qwen。计划必须显示 `transcript_source_status`、来源路径、字符数和
SHA-256；执行前再次验 hash。已有远端 transcript 但 API 无法回读原文时，不自动覆盖。

既有 published episode 的 description、transcript 或其他元数据修复必须以原
episode id 做 update-in-place；不得进入 `publish_actions`，不得被当成新 episode
创建或再次发布。

不自动上传：

- `unlisted` / `private`
- 会员、课程、内部 review、lesson、demo
- 直播回放（`was_live` / `live_status == "was_live"`）

## Scheduled / manual maintenance

推荐顺序：

```bash
# 0. 定时任务先尽量升级到最新 yt-dlp pre-release/nightly
.venv-podcast/bin/python tools/automation/update_yt_dlp.py

# 1. 刷新匿名频道清单（用于发现；会员 teaser 也可能出现在这里）
.venv-podcast/bin/python tools/youtube/fetch_public_videos.py \
  --channel-id UC_5lJHgnMP_lb_VpIiXV0hQ

# 2. 可选刷新 OAuth 全量快照（区分 unlisted/private；必须属于课代表频道）
envs/youtube_env/bin/python3 tools/youtube/fetch_all_videos.py \
  --non-interactive \
  --expected-channel-id UC_5lJHgnMP_lb_VpIiXV0hQ

# 3. 仅下载当前清单中尚未归档、也未被识别为会员的增量条目
./tools/download/download_channel.sh

# 4. 生成候选发现计划（只读远端）
.venv-podcast/bin/python tools/check/build_podcast_sync_plan.py

# 5. 仅验证本次 publication candidates；错误/限流项保持 blocked
.venv-podcast/bin/python tools/youtube/verify_podcast_candidates.py

# 6. 重新生成最终不可变计划；查看 latest.md 并精确批准对应 scope 的 hash
.venv-podcast/bin/python tools/check/build_podcast_sync_plan.py

# 7. 执行批准后的 show notes、transcript 回填或发布（各 scope 的 hash 必须完全一致）
.venv-podcast/bin/python tools/upload/apply_podcast_sync_plan.py \
  --apply-descriptions --approval-hash APPROVED_DESCRIPTION_HASH

.venv-podcast/bin/python tools/upload/apply_podcast_sync_plan.py \
  --apply-transcripts --approval-hash APPROVED_TRANSCRIPT_HASH

# 8. 上传后质检；重排也必须先生成计划，再用同一个 approval hash 执行
.venv-podcast/bin/python tools/check/check_upload_quality.py --n 500
.venv-podcast/bin/python tools/upload/reorder_episodes_by_date.py
.venv-podcast/bin/python tools/upload/reorder_episodes_by_date.py \
  --plan logs/podcast_sync/plans/reorder/latest.json \
  --apply --approval-hash APPROVED_REORDER_HASH
```

周日 09:15 的 launchd 任务自动执行第 0–6 步并停在 plan-only 审批边界。第 0 步
若无法联网升级，只要项目内现有 yt-dlp 仍可运行就记录 warning 并继续；锁定依赖中的
版本是新环境的已知良好基线。第 7–8 步始终需要精确审批对应 scope 和 hash。

## Cleanup policy

不要急着搬目录。先让所有工具读 manifest 语义，再考虑物理整理。

建议的长期目录语义：

```text
archive/
  raw/                 # 只按下载原样存放
  transcripts-human/   # 人工字幕视图/链接
  transcripts-local/   # 本地转录+精校视图/链接
  no-transcript/       # 待转录视图/链接
```

在做物理迁移前，先保证所有现有脚本都不再依赖 `有人工字幕` / `无人工字幕` 作为业务判断。
