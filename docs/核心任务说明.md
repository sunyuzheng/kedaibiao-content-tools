# 核心任务说明

> 本项目核心目标：本地有完整、准确的视频资料，Transistor 上有正确顺序的播客。

---

## 标准工作流

```text
1. 匿名刷新频道清单；可选刷新并校验 OAuth 全量状态
2. 用 archive + member deny set 只下载未见过的增量条目
3. 拉取 Transistor 全量状态生成候选计划，只对 publish candidates 做低频可访问性验证
4. 用验证证据生成最终 immutable plan；未验证候选一律 blocked
5. 人工检查 latest.md 中的精确目标、来源、数量、风险和 approval hash
6. 只用已批准 hash 执行 transcript 回填或 prepare+publish，并逐条回读
7. 发布后质检；重排只允许执行最终 publish payload 中已审核的完整投影
```

## 本地自动化

MacBook 上的 launchd 任务会在每周日 09:15（本地时间）运行：

```bash
launchctl print gui/$(id -u)/com.sunyuzheng.kedaibiao-podcast-sync
```

任务入口：

```bash
python3 tools/automation/sync_podcast.py
```

脚本只做刷新、下载、对账和生成计划，不会自行修改 Transistor。它使用
`logs/podcast_sync.lock` 防止重入，输出 JSONL 结构化日志，并写
`logs/podcast_sync/latest-run.json` heartbeat。7 天后的 JSONL 会压缩，180 天后清理。
launchd 使用 `.venv-podcast/bin/python` 和锁定依赖，不再依赖 Homebrew Python 的偶然环境。
每次运行在访问 YouTube 前都会检查 PyPI，并尽量把项目 yt-dlp 更新到最新
pre-release/nightly。若检查或升级失败，只要原版本仍能通过 `--version` 自检，就记录
warning 并继续；`requirements-podcast.txt` 的固定版本是干净环境的已知良好启动基线。

轻量健康检查（不刷新、不下载，只对账并生成计划）：

```bash
.venv-podcast/bin/python tools/automation/sync_podcast.py \
  --skip-youtube-refresh --skip-download
```

暂停 / 恢复：

```bash
launchctl bootout gui/$(id -u) ~/Library/LaunchAgents/com.sunyuzheng.kedaibiao-podcast-sync.plist
launchctl bootstrap gui/$(id -u) ~/Library/LaunchAgents/com.sunyuzheng.kedaibiao-podcast-sync.plist
```

## 各步骤说明

### 1. 下载

```bash
./tools/download/download_channel.sh
```

- 使用 `.venv-podcast/bin/yt-dlp`；`requirements-podcast.txt` 固定已知良好基线，
  每周任务运行前尽量升级到 PyPI 最新 pre-release/nightly
- 默认匿名读取公开视图，不接触浏览器会话
- 只有明确需要且确认风险时才临时设置
  `YTDLP_COOKIES_BROWSER=chrome ./tools/download/download_channel.sh`
- download archive、本地 member-only info、持久 deny set 共同避免重复访问旧条目
- 新增会员条目只在首次尝试后写入 deny set；非会员错误会令整次 run 失败
- 下载完成后自动运行 `organize_subtitles.py` 分类
- `--ignore-errors` 只用于容忍会员权限条目；其他 `ERROR:` 会令整次 run 失败并报警

**下载内容**：音频（m4a）、info.json、description、字幕（srt）、缩略图（webp）

**物理分类规则**（`tools/organize/organize_subtitles.py`）：
- info.json `subtitles` 字段有 zh/en → `archive/有人工字幕/`
- 其他 → `archive/无人工字幕/`

这些目录只表示历史存储位置。是否进入播客由 manifest 的 YouTube privacy、content class
和 Transistor status 决定；有 `.srt` 也不等于人工字幕。

### 2. 刷新与对账

```bash
envs/youtube_env/bin/python tools/youtube/fetch_all_videos.py \
  --non-interactive \
  --expected-channel-id UC_5lJHgnMP_lb_VpIiXV0hQ

.venv-podcast/bin/python tools/check/build_podcast_sync_plan.py
```

输出：

- `logs/library_manifest/library_manifest.json`
- `logs/library_manifest/library_audit.md`
- `logs/podcast_sync/plans/latest.json`
- `logs/podcast_sync/plans/latest.md`

匿名 public listing 可能包含会员 teaser，只用于发现。候选计划生成后，
`verify_podcast_candidates.py` 只验证本次待发布 ID；其新鲜证据才是 publication gate。
OAuth 全量快照用于补充区分 unlisted/private。清单或候选证据超过 72 小时即阻止发布。已有一个 draft 会被修复和复用；
多个 draft 会阻止该条目，避免猜测哪一个是 canonical。

OAuth 只申请 `youtube.readonly`；它不能上传、删除、评分或管理评论。

### 3. 校验 guests.json

```bash
python3 tools/check/validate_guest_data.py
```

检查内容：
- `all_video_ids` 必须和 `all_urls` 解析出的 video ids 完全一致
- `episode_count` 必须等于 `len(all_video_ids)`
- `primary_video_id` 必须包含在 `all_video_ids` 中
- `primary_url` 必须和 `primary_video_id` 指向同一条视频
- 每个 guest 引用的视频都必须存在于 `guest_video_metadata.json`
- guest 引用视频的 `title` / `published_at` / `view_count` 不能为空

这一步是给 `lizheng.ai/guests` 用的。只更新了 `all_urls`、忘记同步 `all_video_ids` 时，
网站以前会静默漏掉对应 episode。metadata 不全时，子页也会缺标题、观看量和排序依据；现在提交前必须先过这一步。

### 4. 审批与 transcript 回填

先读完整计划：

```bash
open logs/podcast_sync/plans/latest.md
```

计划列出 episode id、YouTube id、本地字幕来源、source status、字符数和内容 hash。
SRT/VTT 会确定性转换为 plain text 后写入官方 `episode[transcript_text]`。公开 API 不支持
原始 SRT 文件字段，因此本地 SRT 仍保留时间戳并作为 canonical source，Transistor 得到全文。

批准 transcript payload 后执行：

```bash
.venv-podcast/bin/python tools/upload/apply_podcast_sync_plan.py \
  --plan logs/podcast_sync/plans/latest.json \
  --apply-transcripts \
  --approval-hash APPROVED_TRANSCRIPT_HASH
```

执行器会重新计算计划和本地文件 hash。若 episode 已有远端 transcript 但 API 不能回读
原文，则保留现状、不盲目覆盖。中断后可用同一计划重跑；已完成条目会跳过，事件写入 ledger。

### 5. 发布

批准 publish payload 后执行：

```bash
.venv-podcast/bin/python tools/upload/apply_podcast_sync_plan.py \
  --plan logs/podcast_sync/plans/latest.json \
  --prepare-and-publish \
  --approval-hash APPROVED_PUBLISH_HASH
```

- `video_id` 是幂等键；远端从 absent 变成有记录时整条 fail-closed。
- 单个现有 draft 会修复，不重新创建。
- create/update 同时写 description、video URL、image URL 和 transcript text。
- description 优先来自本地文件；本地为空时使用新鲜 YouTube 快照并把正文锁进审批
  payload；YouTube 也为空时保留 warning，但不把 description 当作发布硬门槛。
- `published_at` 只通过 `/publish` 端点设置。
- publish plan 同时包含发布后的完整 projected feed 和必要 number/title 改动；历史补档
  不会在未审核重排的情况下单独进入公开 feed。
- 已发布 episode 的历史 description/transcript 修复只允许按原 episode id 更新，
  不得进入新建或重新发布流程。
- 每步 GET 回读；错误返回非零，不能把“create 成功但 publish 失败”报告为成功。

### 6. 质检（上传后必跑）

```bash
.venv-podcast/bin/python tools/check/check_upload_quality.py --n 10
```

检查：

- 标题格式：`E{N}. 标题`
- EP 号与标题前缀一致
- `published_at` 与本地 YouTube 实际日期一致；真实日期恰好是今天不会误报
- `video_url`（YouTube 链接）已设置
- `image_url`（封面图）已设置
- `description` 非空
- 状态为 `published`
- 本地有字幕时，远端必须有 transcript artifact；API 若回传原文则进一步比 hash

### 7. 排序

```bash
.venv-podcast/bin/python tools/upload/reorder_episodes_by_date.py

.venv-podcast/bin/python tools/upload/reorder_episodes_by_date.py \
  --plan logs/podcast_sync/plans/reorder/latest.json \
  --apply \
  --approval-hash APPROVED_REORDER_HASH
```

- 第一条命令只生成计划，不写远端
- 按 YouTube 发布时间升序排序：E1 = 最早，E最大 = 最新
- 任意 published episode 缺少本地日期或 video id 重复时，整个计划被阻止
- 执行前校验旧 number/title/video/status，执行后逐条回读 number/title

## Transistor API 限制

**没有 DELETE 端点**。想隐藏一个 episode 只能设为 draft：
```bash
curl -X PATCH "https://api.transistor.fm/v1/episodes/EPISODE_ID/publish" \
  -H "x-api-key: YOUR_TRANSISTOR_API_KEY" \
  -H "Content-Type: application/x-www-form-urlencoded" \
  -d "episode[status]=draft"
```

官方 API 文档：https://developers.transistor.fm/

---

## 标题格式

Transistor episode 标题格式：**`E{N}. 标题`**（例：`E450. 清华教授：...`）

- 前缀：`E` + 数字 + `. `（英文句号 + 空格）
- 旧格式 `EP{N}_{标题}` 已于 2026-03-29 全部迁移

## 数据架构与权威来源

```
YouTube API
  └── tools/youtube/all_videos_full.json   ← 视频元数据权威来源（852条，含公开/私密/会员）
        用 fetch_all_videos.py 刷新（约38 units，每次全量拉取）

yt-dlp（不消耗 YouTube API 配额）
  └── archive/                              ← 媒体文件（m4a + srt + webp）
        用 tools/download/download_channel.sh 增量同步

guests.json                                ← 嘉宾-视频映射权威来源（125位嘉宾，352期）
  └── `all_video_ids` 必须与 `all_urls` 解析结果完全一致
  └── 推送到 GitHub 后自动驱动 lizheng.ai/guests

guest_video_metadata.json                  ← Guest 页面视频 metadata 权威来源（347条）
  └── 覆盖 title / published_at / view_count
  └── 从 all_videos_full.json 等本地数据整理后提交
```

**规则**：
- Guest 页面视频 metadata（标题/时间/观看量）→ 从 `guest_video_metadata.json` 读
- 更大的全量视频元数据（标题/描述/统计）→ 从 `all_videos_full.json` 读，需要最新时跑 `fetch_all_videos.py`
- 媒体文件 → 从 archive/ 读，缺失时用 yt-dlp 补
- 不把 API 数据和 archive 数据混用（archive 的 info.json 可能过时）
- `lizheng.ai/guests` 的 guest roster 直接读公开 raw 的 `guests.json`
- `lizheng.ai/guests` 的标题、发布时间、观看量以上游 `guest_video_metadata.json` 为准，网站 repo 再维护一个部署快照
- `guests.json` 编辑后必须跑 `python3 tools/check/validate_guest_data.py`

更完整说明见：`docs/网站嘉宾数据说明.md`

## 嘉宾数据工作流（guests.json）

### 单一数据源

```
kedaibiao-channel/guests.json          ← 唯一权威来源，在这里编辑
    ↓  git push
GitHub raw URL（公开可访问）
    ↓  自动同步
lizheng.ai/guests（用户访问时实时拉取）
lizheng.ai/guests 的 SEO 预渲染（Vercel 下次构建时拉取）
```

**不要**在 lizheng-personal-site 里维护任何 guests 数据副本。

上面这句话只针对 **guest roster / 嘉宾-视频映射**。

`/guests/:slug` 页面里展示的 **标题 / 发布时间 / 观看量** 并不是直接从本仓库 raw 拉 `all_videos_full.json`，
因为这份文件当前没有公开发布到 GitHub raw。网站 repo 会维护一份由 `guest_video_metadata.json` 派生出的部署快照。
详见：`docs/网站嘉宾数据说明.md`

### 更新嘉宾数据

```bash
# 在 kedaibiao-channel 目录下
# 1. 编辑 guests.json（添加/修改嘉宾信息）
# 2. 校验一致性
```

在 lizheng-personal-site 推送任意 commit，Vercel 会自动构建并用最新数据重新生成 `dist/public/guests/index.html`。

## Transistor API 已知坑

| 问题 | 原因 | 正确做法 |
|------|------|---------|
| `published_at` 总是今天 | 创建时不支持设置，PATCH /episodes/:id 会忽略 | 必须通过 `/publish` 端点：`episode[status]=published&episode[published_at]=...` |
| `image_url` 没有显示 | 创建时没传或用了 maxresdefault（404 静默失败） | 创建时传 `image_url`，用 `hqdefault.jpg`（非 maxresdefault） |
| 已创建 draft 又重复创建 | 旧候选只看 published，失败重跑看不到 draft | 一次抓全量状态；单 draft 修复复用，多 draft 阻止 |
| SRT 一直没进 Transistor | 旧脚本读取了 SRT 但从未发送字段 | 转纯文本写 `episode[transcript_text]`，执行后检查 transcript artifact |

**最后更新**：2026-07-27
