# 《课代表立正》Show Notes 标准

Show Notes 不是 YouTube description 的副本，也不是关键词清单。它要让第一次看到本期
的人在手机首屏完成三个判断：这期在讲什么、为什么和我有关、为什么值得相信；之后再
用章节、人物与相关资源降低收听和行动成本。

## 默认结构

先使用`PROMOTION.json`中的简短主播介绍和个人站入口（不超过一段介绍加一个链接），
随后进入「本期内容」。读者可先认识立正，再迅速看到本期主题。

1. **主题与冲突**：60–160 字。用具体人物、场景、公司、金额、技术或决策题开场，
   给出本期真正要解决的问题。
2. **听众关联**：30–100 字。明确哪些处境的人最值得听，以及听完能更好地做什么
   判断。不要写空泛的“干货很多”。
3. **这期你会听到**：3–5 条。每条都应是可以独立理解的问题、机制或决策框架，
   不能只是按顺序复述话题。
4. **章节**：只使用未超过音频时长的 YouTube 原生章节，或有证据说明和人工复核记录
   的版本化例外。没有可靠章节就省略这一段；均匀抽取的字幕时间点不是话题边界。
   标题要说明这一段的判断，不写“继续讨论”“更多内容”。
5. **本期嘉宾 / 本期人物**：只写与本期主题有关、且在标题、description 或字幕中
   能找到依据的身份。主播独白不强行增加人物段落。
6. **相关内容**：视频版、文字稿和本期最相关的 0–1 个额外资源。链接名称来自原始
   上下文或本地已核验的视频标题，不能由模型猜测。不要把每一期都变成课程链接合集，
   也不要保留过期活动或旧社区域名。
7. **问问立正**：放在本期内容与资源之后。说明AI根据公开文章、视频和《真本事》
   回答并附出处；当前为每天3次免费提问。文案与链接由`PROMOTION.json`统一管理。
8. **免费社区与AI课程**：先Superlinear Academy免费社区，再AI Builders课程。
   每期已有的具体交流问题可保留在社区入口下，通用宣传由`PROMOTION.json`提供。
   个人站、Ask、社区、课程各承担一个不同动作，不再重复长版主播履历或旧会员广告。

## Discovery 与品牌原则

- 自然写出听众真的会搜索的人名、公司、产品、技术、岗位与问题，不堆同义关键词。
- 顶部主播介绍保持简短；社区、课程与Ask入口放在本期内容之后。
- 事实只能来自本期标题、原 description、字幕或已有的经过核验的 Show Notes。
- 数字、身份、产品关系、合作披露与引语最容易失真，宁可少写，不要补全猜测。
- 语气直接、具体、有判断，但不使用“必听、颠覆、唯一、顶级”等无证据强化词。
- 每一期允许有自己的重心；统一的是信息功能和品牌气质，不是逐字模板。

## 技术约束

- 权威 sidecar 保持为 UTF-8 纯文本，不超过 10,000 字符；不要手写 HTML。
- immutable plan 会把 sidecar 确定性渲染为 `portable_html_v1`：每个信息单元使用
  简单 `<p>`，小标题使用 `<strong>`，问题列表使用字面 `•`，URL 使用 `<a>`。
  这是发布 payload，不改变权威源稿。不要依赖 RSS 中的裸换行；小宇宙会把它们压平。
- 视频版与文字稿的动态标签独立成段，不再在前一行重复同名标签；避免客户端显示
  “观看本期视频版：观看本期视频版”。
- Transistor 动态标签只使用项目 validator 允许的形式。
- 时间戳严格递增，且不得超过播客音频时长。
- 批量来源、生成提示、结构 schema、风格、验证器和最终草稿都必须进入审批哈希；
  promote 前重新读取全部来源并用当前锁定版本验证，任一漂移都停止。
- 关键链接写完整 URL。社区 canonical URL 是
  `https://www.superlinear.academy/`。
- 版本化正文保存为 `podcast_show_notes/<youtube_video_id>.txt`；公开更新仍必须经过
  immutable plan、description approval hash、逐集回读与失败回滚。

## 全量推广刷新

2026-10-02审阅稿位于`logs/show-notes-refresh-20261002/`。历史节目仅按锁定
快照替换明确的通用推广；原正文、章节、人物、完整版链接、合作披露继续保留。
云端YouTube回退简介也应在下一次代码版本切换中采用同一模板，发布前先核对
新期次的准确描述payload；不会自动覆盖历史简介。
